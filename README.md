# dogani

dogani는 할일과 일정을 바탕화면에 띄워 두고 그 자리에서 바로 보고 고치는 가벼운 Windows 앱입니다. 프로그램을 찾아 열 필요 없이 바탕화면에서 오늘 할 일과 이번 달 일정을 확인하고, 누르는 곳에서 바로 편집합니다. 같은 사내망의 동료를 초대하면 서로의 할일과 일정을 실시간으로 함께 보고 고칠 수 있어 업무 현황 공유와 인수인계가 빨라집니다.

## 주요 기능

- **늘 보이는 할일**: 오늘의 할일을 바탕화면 위 작은 창에 띄워 둡니다. 체크박스를 누르면 바로 완료로 표시되고 저장됩니다.
- **한눈에 보는 달력**: 날짜별 진행 상황과 일정, 공휴일, 근태를 한 화면에 봅니다. 날짜를 누르면 할일 창이 그날 노트로 바뀝니다.
- **바로 편집**: 쓰는 대로 서식이 보이는 편집기로 노트를 고치고, 달력에서는 끌어서 일정을 옮깁니다. 저장 버튼 없이 자동으로 저장됩니다.
- **열린 파일 형식**: 노트와 일정은 평범한 마크다운 파일입니다. 어떤 편집기로도 열 수 있고, 폴더를 복사하면 그대로 백업이 됩니다.
- **간단한 공유**: 서버나 계정 없이 초대장 코드 하나로 동료와 스페이스를 함께 씁니다. 초대하지 않은 스페이스는 내 PC 밖으로 나가지 않습니다.
- **가벼운 관리**: 한 번 설치하면 켤 때마다 새 버전을 확인해 자동으로 업데이트합니다.

## 설치

[dogani-setup.exe](https://github.com/icetoppers/dogani/releases/latest/download/dogani-setup.exe)를 받아 실행합니다. Python은 필요 없고 관리자 권한도 묻지 않습니다. 설치가 끝나면 시작 메뉴에서 dogani를 실행합니다.

설치 파일은 처음 한 번만 받으면 됩니다. 이후에는 앱을 켤 때 새 버전을 받아 적용하며, 켜 둔 동안 나온 업데이트는 다음 실행 때 반영됩니다. 설치 파일 자체가 새로 나오면 켜 둔 동안 받아 두었다가 다음에 켤 때 조용히 설치합니다. 설치 파일을 직접 다시 실행해도 기존 설치 위에 덮어 설치됩니다.

## 시작하기

처음 실행하면 노트 폴더를 고르는 창이 뜹니다. 고른 폴더 하나가 스페이스 하나가 됩니다. 스페이스는 트레이의 `스페이스 만들기...` 로 더 만들 수 있습니다.

dogani는 스페이스 안의 다음 파일을 읽습니다.

- 데일리 노트는 `261030 금.md` 또는 `2026-10-30.md` 형식의 이름을 가진 파일입니다.
- 일정 파일은 `2026일정.md` 또는 `일정.md` 입니다.
- 새 노트는 `스페이스/2026.10/261030 금.md` 위치에 만들어집니다.

업무 자료가 섞여 있는 폴더를 골라도 괜찮습니다. 위 형식이 아닌 파일은 읽지 않습니다. 스페이스 폴더에는 설정을 담는 `.dogani` 폴더가 생기며, 점으로 시작하는 폴더는 노트로 읽지 않습니다.

## 화면 구성

화면은 할일 창과 달력 창으로 이루어집니다. 트레이 메뉴의 `할일 표시` 와 `달력 표시` 로 각각 켜고 끕니다. 트레이 아이콘을 클릭할 때마다 달력만, 할일만, 둘 다, 둘 다 닫기 순으로 바뀝니다.

창 위쪽 막대를 끌어 옮기고 가장자리나 모서리를 끌어 크기를 바꿉니다. 위치와 크기는 모니터마다 기억합니다. 창이 화면 밖으로 나가 보이지 않으면 트레이의 `모니터로 불러오기` 에서 모니터를 골라 꺼내 옵니다. Ctrl+휠로 글자 크기를 바꾸고 Ctrl+0으로 되돌립니다.

할일 창은 스페이스가 둘 이상이면 위쪽에 스페이스 탭이 생기고, 탭을 눌러 보는 스페이스를 바꿉니다. 위쪽 막대는 그날 할일의 진행률을 보여 줍니다.

달력 창은 모든 스페이스의 일정을 함께 그립니다. 달력 위(또는 오른쪽 사이드바)의 스페이스·멤버 그룹·멤버·태그 칩을 눌러 일정을 숨기거나 보이고, 칩에 마우스를 올리면 그 일정만 강조됩니다. 화면을 공유할 때는 보이고 싶지 않은 스페이스 칩을 끄면 그 일정이 숨겨집니다.

## 일정

달력 칸을 우클릭하거나 여러 날을 끌어 선택하면 일정을 추가합니다. 일정을 누르면 수정, 끌면 옮기기, Ctrl+끌기는 복사, 가장자리를 끌면 날짜 조절입니다. Ctrl+Z로 마지막 저장을 되돌립니다. 일정 창에서 스페이스를 여러 개 고르면 각 스페이스에 같은 일정이 함께 저장되고, 이후 수정이나 삭제도 모두에 함께 적용됩니다.

일정 파일은 한 줄이 일정 하나입니다. 달력에서 만들어도 되고 다른 편집기로 파일에 직접 적어도 됩니다.

```
261120, 정기 점검, #서버 @홍길동, 전산실, 메모
261124-261126, 교육 기간
**261201** 15:00, 중요 회의
==261120==, 오후 반차, @홍길동
```

- 칸 순서는 `일시, 제목, #태그 @멤버, 장소, 메모` 입니다. 뒤 칸은 비워도 됩니다.
- `**날짜**` 는 중요 일정, `==날짜==` 는 근태(휴가·반차 등)입니다. 근태에 내가 들어 있으면 그날은 빨간 칸으로 보이고 할일 창의 날짜 이동에서 건너뜁니다.
- `@그룹이름` 은 그 그룹 모두, `@all` 은 스페이스 모두를 가리킵니다.
- 자세한 문법은 [SPEC.md](SPEC.md) 3.2절에 있습니다.

노트의 할일에 `📅 2026-11-30` 처럼 날짜를 붙이거나 할일 줄 왼쪽 `⋮⋮` 를 달력에 끌어 놓으면 그 할일이 달력에도 보입니다. 공휴일은 자동으로 받아 표시합니다.

## 편집

노트 전체가 하나의 편집기입니다. 입력을 멈추고 0.7초가 지나면 자동으로 저장되며 Ctrl+S로 바로 저장할 수도 있습니다.

- 체크박스를 클릭하면 완료와 미완료가 바뀌고 바로 저장됩니다.
- Enter를 누르면 목록과 체크박스가 이어지고, 빈 항목에서 Enter를 누르면 목록이 끝납니다.
- Tab과 Shift+Tab으로 목록의 들여쓰기를 조절합니다.
- Ctrl+Z와 Ctrl+Y로 실행을 취소하거나 다시 실행합니다.
- 링크는 클릭하면 열리고, 주소만 적힌 링크는 Ctrl+클릭으로 엽니다.
- 표를 클릭하면 원문으로 바뀌어 편집할 수 있습니다.
- 줄 왼쪽 `⋮⋮` 를 끌어 줄과 하위 줄을 함께 옮깁니다.
- 노트 밖을 클릭하거나 Esc를 누르거나 다른 창으로 전환하면 편집이 끝납니다.

동료나 다른 편집기가 같은 노트를 동시에 고쳐도 서로 다른 줄이면 자동으로 합쳐 저장합니다. 같은 줄을 서로 다르게 고쳤을 때만 어느 쪽을 쓸지 묻습니다.

## 동료와 함께 쓰기

스페이스는 만든 사람의 PC(호스트)에 있는 폴더이며, 초대받은 팀원은 사내망으로 그 폴더를 함께 씁니다. 켜 두는 시간이 긴 PC에서 스페이스를 만드는 것이 좋습니다. 호스트가 꺼져 있는 동안 그 스페이스는 읽기 전용이 되고, 다른 스페이스는 그대로 쓸 수 있습니다.

### 초대하기

1. 트레이에서 스페이스 이름을 열고 `새 초대장 만들기` 를 누릅니다. 호스트 주소와 초대장 코드가 복사됩니다.
2. 복사한 내용을 메신저로 초대할 사람에게 보냅니다. 초대장은 한 사람당 하나이며 15분 안에 한 번만 쓸 수 있습니다.
3. 초대받은 사람은 트레이의 `다른 스페이스에 참여하기...` 를 누르고 호스트 주소와 초대장 코드를 입력합니다.
4. 호스트 PC에 Windows 방화벽 알림이 뜨면 허용을 누릅니다. 허용하지 않으면 팀원이 접속할 수 없습니다.

한 번 참여한 PC는 다시 묻지 않습니다. 팀원에게 보이는 이름은 트레이의 `내 이름` 이며 처음에는 PC 이름으로 정해집니다.

### 권한과 멤버 그룹

새로 만든 스페이스의 팀원은 기본적으로 보기만 할 수 있습니다. 호스트 PC의 트레이 > 스페이스 메뉴에서 바꿉니다.

- `기본 권한: 보기만` 체크를 풀면 그룹이 없는 팀원 모두가 편집할 수 있습니다.
- `멤버 그룹` 에서 그룹을 만들고 그룹마다 편집 허용을 정합니다. 팀원은 하나라도 편집 허용 그룹에 들어 있으면 편집할 수 있습니다.
- 팀원 메뉴의 `권한` 에서 사람마다 따로 정할 수도 있습니다.
- 달력 사이드바에서 멤버 칩을 그룹 칩에 끌어 놓거나 칩을 우클릭해도 그룹을 고칠 수 있습니다.

### 관리

- 팀원이 PC를 바꾸면 팀원 메뉴의 `다시 초대` 로 새 초대장을 보냅니다. 새 PC에서 참여하면 이름은 그대로 유지되고 예전 PC는 더 접속하지 못합니다.
- `내보내기` 로 팀원을 뺍니다. 다른 팀원에게는 영향이 없습니다.
- 호스트의 IP가 바뀌어도 같은 사내망이라면 팀원의 dogani가 호스트를 다시 찾습니다. 찾지 못하면 팀원이 참여 스페이스 메뉴의 `호스트 주소 바꾸기...` 에 새 주소를 입력합니다. IP가 자주 바뀐다면 호스트 PC의 IP를 고정해 두는 것이 좋습니다.
- 스페이스 폴더를 옮기려면 `대상 폴더 변경하기...` 를 씁니다. 팀원은 그대로 이어집니다.
- 호스트를 다른 PC로 옮기려면 스페이스 폴더와 `%APPDATA%\dogani\team\<스페이스id>.json` 파일을 새 PC로 복사한 뒤 새 PC에서 그 폴더로 스페이스를 만듭니다.
- 스페이스는 평범한 폴더이므로 폴더를 복사하는 것으로 백업할 수 있습니다.

## 트레이 메뉴

트레이 메뉴에서는 창 표시, 내 이름, 스페이스 관리 외에 다음을 설정합니다.

- `클릭 시 깨어나기` 를 켜면 다른 프로그램을 쓰는 동안 할일·달력 창이 옅게 멈춰 있습니다. 한 번 클릭하면 두 창이 함께 깨어나고 그다음 클릭부터 동작하며, 창을 눌러도 다른 프로그램 위로 올라오지 않습니다.
- `다크 테마` 로 어두운 화면을 씁니다.
- `Windows 시작 시 자동 실행` 으로 로그인할 때 dogani를 켭니다.

창은 바탕화면에 붙어 있어 Win+D를 눌러도 남아 있습니다. 트레이 아이콘이 초록색이면 정상 동작 중이고, 회색이면 포트가 이미 사용 중이라 스페이스를 열지 못한 상태입니다.

설정은 `%APPDATA%\dogani\dogani.json` 에 저장됩니다. 환경변수 `DOGANI_HOME` 으로 위치를 바꿀 수 있습니다.

## 보안

dogani는 사내망 안에서 쓰는 것을 전제로 합니다. 외부망에서의 사용은 고려하지 않았습니다.

- 통신은 암호화하지 않은 HTTP를 씁니다. 같은 망에서 패킷을 엿보면 노트 내용과 토큰이 드러날 수 있습니다.
- 요청에 붙는 식별 키는 공개된 코드에 들어 있는 고정값입니다. 웹브라우저로 바로 여는 것을 막을 뿐 비밀번호 역할은 하지 않습니다.
- 스페이스 출입은 일회용 초대장과 그로부터 받은 토큰으로만 확인합니다. 초대하지 않은 스페이스에는 다른 PC가 접속할 수 없습니다.
- 팀원은 스페이스의 노트와 일정을 모두 볼 수 있습니다. 편집은 권한이 있는 팀원만 할 수 있습니다.
- 업데이트는 배포 서명이 맞을 때만 적용합니다.

## 개발에 참여하기

저장소를 포크해 직접 고치고 빌드할 수 있습니다. 구성, 데이터 형식, API, 배포 구조, 시험은 [SPEC.md](SPEC.md), 화면 규칙은 [DESIGN.md](DESIGN.md)에 정리되어 있습니다.

### 소스로 실행

Python 3.10 이상이 필요하며, 빌드와 같은 3.13을 권장합니다.

```
app\install.bat
app\run.bat
```

`app\run.bat --dir "D:\업무" --port 8765` 처럼 스페이스 폴더와 포트를 지정할 수 있습니다. 소스로 실행할 때는 자동 업데이트를 받지 않습니다. UI 파일을 저장하면 창이 새로 고쳐지고, 파이썬 파일을 저장하면 앱이 다시 시작됩니다.

### 시험

저장소 루트에서 실행합니다. 실제 설정과 노트는 건드리지 않습니다. 시험별 대상은 [SPEC.md](SPEC.md) 9절에 있습니다.

```
python -m unittest discover -s tests -v
node --test tests/
python tests/e2e_ui.py
```

### 편집기 빌드

편집기는 CodeMirror 6 기반이며 소스는 `app/editor/src/main.js` 에 있습니다. 고친 뒤 `app/editor/build.bat` 을 실행하면 `app/ui/vendor/editor.js` 가 만들어집니다. 이 과정에는 Node.js가 필요합니다.

### exe 빌드

`build.bat` 을 실행하면 `dist\dogani\` 폴더에 실행 파일이 만들어집니다. 빌드에는 Python 3.13이 필요합니다. Inno Setup 6이 설치되어 있으면 설치 파일 `dist\dogani-setup.exe` 도 함께 만들어집니다.

exe는 앱 코드를 담고 있지 않고 실행할 때 내려받습니다. 따라서 `app\deps.py` 에 외부 라이브러리를 추가했거나 `app\launcher.py` 를 고쳤을 때만 exe를 다시 빌드하면 됩니다.

### 배포

버전 태그를 GitHub에 올리면 배포됩니다. 태그 이름은 `v26.11.09.01` 처럼 연, 월, 일, 순번으로 짓습니다. 커밋을 push하는 것만으로는 사용자에게 업데이트가 나가지 않으며, 배포 서명(`app/release.sig`)이 없는 태그는 받지 않습니다. 절차는 [SPEC.md](SPEC.md) 6절에 있습니다.
